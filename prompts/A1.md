# Agent A1: DI container

## You own
internal/di/ only. Implement core.Container (the stub in internal/di/di.go
fixes the constructor `di.New() *Container`).

## Build
- Register: constructor providers (func returning T or (T, error)), value
  providers, Bind/Factory (first result assignable to Token.Type; check at
  Register and return a clear error otherwise), Named tokens. Reject
  RequestScoped with a clear error. Reject non-func ctors, ctors with no
  results, a second non-error result, variadic ctors.
- Parameter objects: a parameter whose type is a struct embedding core.In has
  each exported field injected by type, honouring `name:"..."` and
  `optional:"true"`. Non-struct optional deps are not supported.
- Resolution by Token with memoisation for Singleton (instantiate once,
  safe for concurrent Resolve after Validate) and a fresh instance per
  injection for Transient.
- Ownership + visibility: Register takes an owner module (nil = framework
  provider visible everywhere). Resolve(tok, from) chooses the candidate owned
  by `from` first, else candidates for which Visibility.Visible(from, owner,
  tok) is true. More than one visible candidate from different modules is an
  ambiguity error naming the modules. Dependencies of a provider are resolved
  as seen from the provider's OWNER module. Default visibility: allow all.
- Errors are *core.ResolveError with the full Path (outermost first),
  Reason ("no provider", "not visible from module x", "cycle", "constructor
  failed", "ambiguous"), and Hint (e.g. "*UsersService is provided by module
  users; add it to Exports" or "import module users").
- Cycle detection with the full cycle in Path: A -> B -> C -> A.
- Validate(): resolve every registered provider (all owners) so every problem
  surfaces at startup; collect all distinct problems with errors.Join.
- Invoke(fn, from): call any func with injected params; returns results; a
  trailing error result becomes err (not included in results).
- Instances(): singletons in creation order with owner and enhancer kind.
  Enhancers(): instances of providers with Enhancer != EnhancerNone in
  registration order (instantiate them if needed).
- Precompute per-provider parameter plans at Register/Validate time; after
  Validate a singleton Resolve must be a single map lookup under RLock (or
  lock-free) with zero allocations for cached singletons.

## Acceptance
- Table-driven tests: chains, interfaces via Bind, values, factories, named
  + optional params, ctor errors wrapped, cycles, missing deps with hint,
  visibility (with a custom Visibility), ambiguity, transient vs singleton
  identity, Invoke, Instances order, Enhancers, concurrent Resolve under -race.
- Benchmark: BenchmarkResolveSingleton shows 0 allocs/op.
- Coverage >= 90% for internal/di.
- Handoff: docs/handoff/a1.md.

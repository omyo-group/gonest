# Agent C1: example SaaS app and documentation

## You own
examples/ and docs/guide/. Read every file in docs/handoff/ first.

## Build
- examples/saas: a small multi-tenant API using every feature:
  config + logger modules; an auth module (HS256 JWT guard implemented with the
  standard library only — crypto/hmac — plus CurrentUser via SetMetadata/
  Ctx values and a roles guard using SetMetadata); a tenants module (tenant
  resolved from X-Tenant-ID by middleware via Configure, exported
  TenantService); a projects module (CRUD with validation, pagination query
  DTO with defaults, 404/409 errors, NoContent delete); a timing interceptor;
  a custom exception filter mapping a domain error to 422; OnModuleInit
  seeding in-memory data; OpenAPI at /docs and /openapi.json; graceful
  shutdown. main.go in examples/saas/cmd/server.
- Tests for the example using gonesttest only.
- examples/bench: benchmark comparing a Gonest endpoint with raw Gin (same
  handler logic), reporting ns/op, B/op, allocs/op; record results in
  docs/guide/performance.md.
- docs/guide: index.md, getting-started.md, modules.md, providers.md,
  controllers.md, pipeline.md (with the order diagram in ASCII or mermaid),
  configuration.md, logging.md, testing.md, openapi.md, cli.md,
  coming-from-nestjs.md (side-by-side decorator vs Gonest code), performance.md.
- Root README.md: pitch, install, 30-line quick start, feature table,
  links to the guide, status (v0.1, pre-1.0 API).
- Every snippet in docs/guide must come from compiled code (example app,
  example_test.go files or the contract example). Add `// docs:` markers if
  helpful.

## Acceptance
- `go run ./examples/saas/cmd/server` boots; /docs lists every endpoint;
  `go test -race ./examples/...` passes. Handoff: docs/handoff/c1.md.

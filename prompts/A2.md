# Agent A2: HTTP pipeline

## You own
internal/pipeline/ only. Implement the Mounter whose signatures are stubbed in
internal/pipeline/pipeline.go (New, SetGlobals, Mount, InstallFallbacks).
You receive constructed controller instances; you never touch the DI container.

## Build
- Router implementation of core.Router with Prefix, Use (applies to routes
  declared after it), Group (nested prefix + options), the method helpers and
  Handle. Mount calls ctrl.Routes(r), then registers every route on the gin
  engine (GlobalPrefix + controller prefix + group prefixes + path; normalise
  slashes; empty path means the prefix itself) and adds a *core.RouteInfo to
  Options.Routes. RouteInfo.ControllerConfig = merged Use options (controller
  and groups), Config = route options, Module = module name, Controller =
  reflect.TypeOf(ctrl). Duplicate method+path: return an error (recover gin's
  panic or check beforehand); never panic.
- Middleware: for each route call mw(method, fullPath) once at mount time and
  register those gin handlers before the pipeline handler.
- Binder compiled per In type at mount (cache by type): precompute field
  index paths, source, name, kind converter, default values. Sources: path,
  query, header, form, json body (see docs/contracts.md "Input binding rules").
  Embedded structs (non core.In) are flattened. core.Empty and struct{} need no
  work. Validation with one shared *validator.Validate created in New (use
  RegisterTagNameFunc so errors report the client-facing name); FieldError list
  in a 400 HTTPError "validation failed". Conversion errors -> 400 with rule "type".
  Malformed JSON -> 400 "invalid JSON body".
- Pipeline per route, composed at mount into a closure; per request only walk
  slices: guards (global, controller, route) -> interceptors (global outermost,
  then controller, route) wrapping [bind+validate -> pipes (global, controller,
  route) -> handler.Call]. Guards false -> 403 "Forbidden resource".
  Globals come from SetGlobals (store in an atomic pointer read per request,
  or compose lazily once on first request — globals may be set after Mount).
- Response: raw handlers write themselves. Otherwise status = ctx.StatusOverride()
  or route.SuccessStatus(); NoContent -> 204 empty; else JSON (gin's c.JSON).
- Errors: filters route -> controller -> global; first Catch true wins; else
  default filter: *HTTPError -> its Body(); errors.As for wrapped HTTPError;
  anything else -> 500 "Internal Server Error" and log the real error with
  ctx.Logger() (method, path, error). Recover panics in the pipeline -> 500,
  logged with stack. If a filter panics, fall back to the default.
- Ctx: core.NewCtx(gc, route, logger) once per request. Use a sync.Pool only if
  benchmarks justify it and it is safe (a Ctx may escape into goroutines; if
  pooled, document it). Prefer correctness.
- InstallFallbacks: engine.NoRoute -> 404 JSON ErrorBody "Cannot GET /x"
  (NestJS wording), NoMethod -> 405 (set HandleMethodNotAllowed).

## Acceptance
- httptest tests: every binding source and type, defaults, slices, pointers,
  validation messages with client names, malformed JSON, pipeline ORDER (record
  a trace through global/controller/route guards, interceptors, pipes),
  interceptor result replacement and error handling, filter precedence,
  panic recovery, duplicate routes, Group/Use scoping, GlobalPrefix, status
  rules (POST 201, Status option, SetStatus, NoContent), raw handlers, fallbacks.
- Benchmarks: BenchmarkRawGin vs BenchmarkGonestHandle for the same JSON
  endpoint with a path param and a query param (httptest recorder, gin in
  release mode). Report numbers in your handoff; aim for <5% overhead on
  ns/op beyond binding, and explain allocations.
- Coverage >= 85%. Handoff: docs/handoff/a2.md.

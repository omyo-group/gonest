# Handoff A2: HTTP pipeline (`internal/pipeline`)

## What was built

| File | Content |
|---|---|
| `pipeline.go` | `Options`, `Globals`, `MiddlewareFor`, `Mounter` (`New`, `SetGlobals`, `Mount`, `InstallFallbacks`), route compilation, gin registration with panic-to-error |
| `router.go` | `core.Router` implementation (`Prefix`, `Use`, `Group`, method helpers, `Handle`) |
| `binder.go` | input binder compiled per type: sources, defaults, slices, pointers, files, JSON body |
| `convert.go` | scalar converters (ints, uints, floats, bool, string, `time.Time`, `time.Duration`, `encoding.TextUnmarshaler`, pointers) |
| `validation.go` | default validator (client-facing names), validator error -> `core.ValidationErrors`, messages |
| `exec.go` | per-request execution: guards, interceptor chain, bind, pipes, handler, response, filters, default filter, panic recovery |
| `*_test.go` | httptest suites + benchmarks |

## Public API (unchanged seam signatures)

```go
type Options struct { Engine *gin.Engine; Logger *slog.Logger; Routes *core.RouteTable; GlobalPrefix string; Validator *validator.Validate }
type Globals struct { Guards []core.Guard; Interceptors []core.Interceptor; Pipes []core.Pipe; Filters []core.ExceptionFilter }
type MiddlewareFor func(method, fullPath string) []gin.HandlerFunc
func New(opts Options) *Mounter
func (m *Mounter) SetGlobals(g Globals)
func (m *Mounter) Mount(ctrl core.Controller, module string, mw MiddlewareFor) ([]*core.RouteInfo, error)
func (m *Mounter) InstallFallbacks()
```

Nothing else is exported.

## Behaviour and decisions

- **Paths**: `GlobalPrefix + Prefix + group prefixes + path`, split on `/`,
  empty segments dropped, leading `/`, no trailing slash (`""` and `"/"` mean
  the prefix itself). `Prefix` applies to all routes of the controller
  whatever the call order (also when called inside a group).
- **Use / Group**: `Use` affects routes declared after it in that router or
  group; a group snapshots its parent's options, then adds its own options.
  `RouteInfo.ControllerConfig` = parent `Use` + group opts + group `Use`;
  `RouteInfo.Config` = route opts.
- **Mount is all-or-nothing for validation**: duplicate method+path (across
  controllers or within one), bad input types, path fields naming a missing
  `:param`, invalid defaults, nil/zero handlers, invalid methods, panics in
  `Routes` -> joined error, nothing registered. A gin rejection (e.g. a
  wildcard conflict `/x/:id` vs `/x/:name`) is recovered into an error; routes
  of that controller registered before it stay registered (returned in the
  slice).
- **Middleware**: `mw(method, RouteInfo.Path)` is called once per route at
  mount; the path **includes GlobalPrefix**. B1: strip it if Nest semantics
  are wanted (see docs/contract-changes.md).
- **Globals**: stored in an `atomic.Pointer`, read once per request, so
  `SetGlobals` before or after `Mount`, even concurrently with traffic, is safe.
- **Order**: guards global -> controller -> route; interceptors global
  (outermost) -> controller -> route; inside the innermost `next`: bind +
  validate -> pipes global -> controller -> route -> handler. Filters: route
  -> controller -> global -> default.
- **Interceptor retries**: binding is memoised per request, so an interceptor
  calling `next()` twice does not re-read the body; pipes and handler re-run.
- **Pipes** must return a value of exactly `ArgMeta.Type`; otherwise 500 with a
  logged error. Raw handlers skip binding and pipes.
- **Binding** (see docs/contracts.md, plus extensions proposed in
  docs/contract-changes.md): `*In` inputs, `TextUnmarshaler` scalars,
  `*multipart.FileHeader`/`[]*multipart.FileHeader` form files, empty
  non-string values = missing, slices split on commas and drop empty items,
  header lookup by canonical key, `core.In` embedded is ignored, other
  embedded structs are flattened (embedded pointers rejected). JSON body:
  decoded only when the struct has a json field and the body is non-empty;
  afterwards every non-json exported field is reset, so the body cannot set
  path/query/untagged fields. Trailing data after the JSON value is rejected.
- **Errors**: conversion errors -> 400 "validation failed" with
  `FieldError{Rule:"type", Param: <go type>}`; JSON type mismatch -> same, with
  the JSON path (`address.zip`); malformed JSON -> 400 "invalid JSON body";
  validator errors -> 400 "validation failed" with client names
  (`items[1].name`, `X-Tenant`) and `Source` (`body`, `query`, `path`,
  `header`, `form`).
- **Default filter**: `errors.As` `*HTTPError` (status kept; >= 500 logged);
  bare `core.ValidationErrors` -> 400; panics -> 500 logged with stack;
  anything else -> 500 "Internal Server Error" logged with method, route path
  and error. Invalid statuses (outside 100..599) -> 500. If the response was
  already written (raw handler), the error is only logged. A panicking filter
  is logged and the default filter answers. `http.ErrAbortHandler` panics are
  re-raised.
- **Response**: status = `ctx.SetStatus` value, else `RouteInfo.SuccessStatus()`
  (precomputed). `NoContent` result -> status with empty body; otherwise
  `gin.Context.JSON`.
- **Fallbacks**: `NoRoute` -> 404 `Cannot GET /x`; `HandleMethodNotAllowed` +
  `NoMethod` -> 405 `Cannot POST /x`, both as `ErrorBody`.
- **Ctx**: `core.NewCtx` once per request, not pooled (it may escape into
  goroutines). Logger = `Options.Logger` (nil -> `slog.Default()` at request time).
- **Validator**: `validator.New(WithRequiredStructEnabled)` + tag name func
  using path/query/header/form/json names. A custom `Options.Validator` is
  used as is (its own field names). Validation is skipped entirely for types
  without any `validate` tag.

## Coverage and benchmarks

`go test -race -cover ./internal/pipeline/` -> **97.1%**.

Benchmarks: shared 2-CPU machine, `GOMAXPROCS=1`, 6 runs x 500k iterations,
gin release mode, httptest recorder (allocations include the recorder).

| Benchmark | median ns/op | min ns/op | B/op | allocs |
|---|---|---|---|---|
| RawGin (path + query -> JSON) | 1848 | 1638 | 1504 | 14 |
| GonestHandle (same) | 2246 | 2023 | 1568 | 17 |
| GonestHandleValidated (+2 rules) | 2819 | 2276 | 1568 | 17 |
| GonestHandleEnhancers (+guard, interceptor, pipe) | 2484 | 2286 | 1656 | 19 |
| RawGinNoInput | 1301 | 1202 | 1072 | 11 |
| GonestNoInput (pipeline only) | 1453 | 1301 | 1104 | 12 |
| RawGinJSONBody (ShouldBindJSON + binding:"required") | 2990 | 2756 | 2072 | 21 |
| GonestJSONBody (json + validate:"required") | 3516 | 3036 | 2136 | 23 |

Run-to-run noise on this machine is +-15%, so read the pairs, not single numbers.

- **Pipeline without binding**: +1 alloc (the 32 B `*core.Ctx`); +100 to
  150 ns (min-to-min +8%, median +12%; one isolated 2M-iteration run measured
  +3.5%). In CPU profiles the run/guard/interceptor code is about 4% of
  samples; the rest of the gap is the Ctx allocation and its GC cost.
- **Binding path + query**: +3 allocs over raw gin: Ctx, `reflect.New(In)`,
  and boxing the `In` value into `any` for `Handler.Call`. Using
  `Handle[*In, Out]` removes the boxing allocation. Binding costs about
  200 to 250 ns (reflect setters, `GetQueryArray`); the query parse itself is
  shared with raw gin's `c.Query`.
- **JSON body**: +10% (min) to +18% (median) versus gin's `ShouldBindJSON`;
  +2 allocs (Ctx and boxing).

The <5% target is **not** clearly met on this machine: the pipeline alone
lands at roughly +4 to +12% depending on the run, almost all of it the
per-request Ctx allocation, which the frozen `core.NewCtx` contract and the
no-pooling decision make unavoidable. Binding adds a fixed ~200 ns reflection
cost that a hand-written handler does not pay. Re-measure on a quiet machine
before drawing conclusions.

## Known gaps

- Mount is not fully atomic when gin itself rejects a route after earlier
  routes of the same controller were registered (gin offers no dry run).
- No request body size limit (leave to middleware / `http.MaxBytesReader`).
- JSON decoding uses `encoding/json` (gin's renderer also uses
  `encoding/json` by default). `DisallowUnknownFields` / whitelist mode is not
  offered.
- No content-type check before JSON decoding (as NestJS by default).
- Validation messages are English only; unknown rules render as
  `failed the "rule" rule (param)`.
- `Ctx` is allocated per request; pooling was rejected for safety.

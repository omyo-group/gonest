# Handoff A1: DI container (internal/di)

## What was built
`di.New() *Container`, a full implementation of `core.Container`.

Files:
- `internal/di/di.go`: Container, Register (provider checks), SetVisibility,
  Validate, Resolve (fast path), Invoke, Instances, Enhancers.
- `internal/di/resolve.go`: provider selection (ownership + visibility),
  recursive resolution, cycle detection, error construction and hints,
  Validate de-duplication.
- `internal/di/plan.go`: per-function-type injection plans (parameters,
  parameter objects with `name` / `optional` tags), cached by `reflect.Type`;
  reflective call with panic recovery.
- `internal/di/di_test.go`: table-driven tests and benchmarks.

## Public API
Only what the seam requires: `di.New`, `*Container` and its `core.Container`
methods. Everything else is unexported.

## Behaviour and decisions
- **Register** rejects: nil or non-func ctor, no results, more than 2 results,
  a second result that is not `error`, a ctor returning only `error`, variadic
  ctors, a first result not assignable to `Token.Type` (Bind/Factory),
  `RequestScoped` and unknown scopes, value providers whose value is not
  assignable (or nil for a non-nilable type), unknown kinds, enhancer
  providers whose token type does not implement Guard/Interceptor/Pipe/
  ExceptionFilter, parameter objects with unexported fields or an invalid
  `optional` tag, and the same token twice for the same owner (including nil).
  Errors read `gonest: cannot register <provider> in module <m>: <why>`.
- **Selection** for `Resolve(tok, from)`: (1) the provider owned by `from`
  (for `from == nil`, the framework provider); (2) the single module provider
  for which `Visibility.Visible(from, owner, tok)` is true (default: all
  visible); more than one is `ambiguous` with the module names in the Hint;
  (3) a framework provider (nil owner) as a fallback, never filtered by
  Visibility. So a module that provides e.g. `*slog.Logger` overrides the
  framework one for everyone who can see it.
- Dependencies of a provider are resolved as seen from its **owner**.
- **Errors** are `*core.ResolveError`, Path outermost first (Invoke's root is
  the function's first result type, or the func type). Reasons are exactly
  `no provider`, `not visible from module x` (or `... from the application
  root`), `ambiguous`, `cycle`, `constructor failed` (Err = ctor error or
  panic, so `errors.Is` works). `Module` is the module where the failing
  lookup happened (the dependent's owner). Hints: other names of the same type,
  pointer/non-pointer mismatch, registered types implementing a missing
  interface (suggesting `Bind[I]`), the owning module to export/import.
- **Optional** fields (`optional:"true"`, parameter objects only) are left zero
  when the provider is missing or not visible; ambiguity and failures of an
  existing provider still propagate.
- **Validate** resolves every entry from its owner, building all singletons;
  for transient providers it walks dependencies but does not call the
  constructor. Problems sharing a root cause (same failing token + reason +
  module, or the same cycle members) are reported once, joined with
  `errors.Join`.
- A failing singleton constructor is called at most once; the failure is
  cached and re-reported.
- **Instances()** lists built singletons including value providers (values
  are recorded at Register), in creation order. Transient instances are not
  tracked.
- **Enhancers()** builds enhancer providers if needed (from their owner), in
  registration order; ones that fail are skipped (Validate reports them).
- **Invoke** resolves arguments under the lock, then calls `fn` with the lock
  released (so Configure functions may use the container). A trailing `error`
  result is returned as `err` and removed from the results; a panic in `fn`
  becomes an error.
- **Concurrency**: one `sync.RWMutex`. Fast path: `RLock` + one map lookup of
  `(token, from)` in a selection cache + `built` check; zero allocations.
  Everything else runs under the write lock. The selection cache is cleared by
  Register and SetVisibility. Constructors run under the lock, so a
  constructor must not call back into the same container (it would deadlock);
  Invoke'd functions may.

## Known gaps
- Ctor re-entrancy into the same container deadlocks (documented).
- Parameter objects are struct values only (no pointer to an In struct, no
  nested parameter objects); `optional` is only available on their fields.
- `Enhancers()` cannot report errors (contract has no error result); rely on
  Validate.
- The container does not provide itself; B1 can `Register(core.Value(c), nil)`
  if needed.

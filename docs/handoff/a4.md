# Handoff A4: CLI (`cmd/gonest`, `internal/codegen`)

## Built
- `cmd/gonest`: cobra CLI. `run(args, stdout, stderr, workdir)` is the testable entry point.
- `internal/codegen`: names (`ParseName`), templates (embedded `templates/new`, `templates/gen`),
  `NewProject`, `Generate`, `Plan.Apply` (atomic writes, conflict detection, dry run),
  `RegisterInModule` (go/ast module editing), `Info`, `Version` const (`0.1.0`).

## Commands
- `gonest new <name> [--module path] [--dir path] [--gonest-replace PATH] [--minimal] [--force] [--dry-run]`
- `gonest generate|g <module|controller|service|guard|interceptor|filter|pipe|dto> <name> [--path dir] [--flat] [--force] [--dry-run]`
  (aliases mo, co, s, gu, in, f, pi). Default directory `internal/<snake name>`; `--path` is the target
  directory itself; `--flat` without `--path` uses the working directory. A trailing kind word is dropped
  (`auth-guard` -> `AuthGuard` in `internal/auth`). Package name comes from existing Go files in the
  directory, else the directory name.
- `gonest info`: Go, Gonest, Gin (from build info, else from the project's go.mod).

## Decisions
- `--minimal` (new): omits `config.ForRoot` / `logger.ForRoot` wiring, `config.go` and `.env.example`;
  the project then needs only the root package. Default (full) output targets the planned A3 API:
  `config.ForRoot[AppConfig](config.Options{})`, `logger.ForRoot(logger.Options{})`,
  `gonest.Get[*app.AppConfig]` in main. Full output is covered by golden tests but not compiled
  (modules/config and modules/logger were empty when this was written); compile it once A3 merges.
- Registration: controller -> `Controllers: NewXController`; service and guard ->
  `Providers: gonest.Provide(NewX)`. Located via go/parser; the element is spliced at the AST-reported
  offset, then re-parsed and gofmt'd (comments survive). Missing field is added; duplicate is a no-op;
  zero or several `&gonest.Module{}` literals -> a printed hint instead.
- A generated controller injects the service when `<name>_service.go` already exists beside it.
- Existing files are never overwritten without `--force`; all conflicts are checked before any write.
- Generated project requires `github.com/omyo/gonest v0.1.0`; run `go mod tidy` (no go.sum is generated).

## Tests
`go test -race ./cmd/... ./internal/codegen/...`: golden files in `internal/codegen/testdata`
(`go test ./internal/codegen -update` to refresh); end-to-end test in `cmd/gonest/main_test.go`
scaffolds with `--minimal`, generates all components, then runs `go build`, `go vet`, `go test` in the
project (copies repo go.sum, `GOFLAGS=-mod=mod`; skipped without `go`). Coverage: codegen 90.5%, cmd 91.8%.

## Known gaps
- Only Providers/Controllers are edited; new modules are not auto-added to the root `Imports` (a hint is printed).
- Interceptors, filters and pipes are not registered anywhere automatically (they are wired by the user via
  `UseX` or `AppX`).
- Module/package names with underscores follow the spec (`user_profile`) rather than Go style.

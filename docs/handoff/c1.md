## The SaaS example

| Package | Demonstrates |
|---|---|
| `settings` | `Config` struct loaded by `config.ForRoot` with prefix `SAAS_`, `secret:"true"`, validation |
| `auth` | HS256 JWT with `crypto/hmac` only (fixed header, rejects `alg:none`, expiry); `JWTGuard` (401 via `HTTPError`), `CurrentUser` via `Ctx.Set`/`CtxValue`; `Roles(...)` = `SetMetadata` + `RolesGuard`; optional injected `Clock` (parameter object, `optional:"true"`); `POST /auth/login`, `GET /auth/me` |
| `tenants` | tenant from `X-Tenant-ID` resolved by gin middleware bound in `Module.Configure` (`ForRoutes(ForPath("/projects/*"), ...)`); exported `*Service`; `MemberGuard` (`GuardFunc`); embedded `TenantHeader` documents the header in OpenAPI |
| `projects` | CRUD with `Bind[Repository]`, pagination query DTO with defaults and bounds, 404/409 `HTTPError`s, `NoContent` delete restricted to admins, `TrimPipe` (route pipe), `DomainErrorFilter` (controller filter, domain error -> 422), `OnModuleInit` seeding, `OnApplicationShutdown`, `Page[T]` generic output |
| `platform` | global `TimingInterceptor` via `AppInterceptor` (injected logger, sets `X-Response-Time`), public `/health` |
| `app` | root module as a function (dynamic modules), `logger.ForRoot` + `RequestLogger` with `Exclude(/health)`, `openapi.Module` with bearer scheme; integration tests |
| `cmd/server` | `gonest.New`, `Get[*settings.Config]`, `config.Redacted`, `Listen` (graceful shutdown, 15 s timeout) |

Verified live (`go run ./examples/saas/cmd/server`): boots, 12 routes mapped,
`/openapi.json` lists all 9 public endpoints, `/docs` and its assets served,
SIGTERM runs `OnApplicationShutdown` and exits cleanly.

Tests (gonesttest + stdlib only): 36-case HTTP table (each case a fresh app),
headers, OpenAPI content, provider overrides (`Clock`, `Repository`),
config success/failure, lifecycle, `Serve` + cancel, unit tests of JWT,
guards (`NewCtx`), filter (`ResponseOf`), pipe, repository. Coverage of
`examples/saas/...` with `-coverpkg`: 89.2% (main.go is the uncovered part).

## Benchmarks (docs/guide/performance.md)

GOMAXPROCS=1, 12 interleaved rounds x 200k iterations, shared 2-vCPU Xeon,
min ns/op (median in the guide):

| Scenario | Gin | Gonest | allocs |
|---|---|---|---|
| NoInput | 1240 | 1379 (+11%) | 11 -> 12 |
| PathQuery (validated) | 1700 | 2188 (+29%) | 14 -> 17 |
| PathQuery, `*In`, no validate | 1700 | 1894 (+11%) | 14 -> 16 |
| Guard + interceptor | 1721 | 2405 (+40%) | 14 -> 19 |
| JSON body | 2540 | 2871 (+13%) | 21 -> 23 |

The 5% target is not met on these no-op endpoints; overhead is a constant
0.1 to 0.7 µs (Ctx allocation, reflective binding ~200 ns, validator ~300 ns,
interceptor closures). Reported as is.

## Bugs found

None requiring a framework fix. Observations (behaviour as designed, worth
considering before 1.0):

1. `logger.RequestLogger` does not call `Ctx.SetLogger`, so framework error
   logs ("gonest: unhandled error") lack `request_id`. Workaround documented in
   logging.md: a global interceptor doing `ctx.SetLogger(logger.FromCtx(ctx))`
   (`examples/guide/config_test.go`). Errors raised by guards still use the
   application logger, since guards run before interceptors.
2. Global guards are invisible to OpenAPI (known B2 gap); the example uses
   controller-level guards + `gonest.Security` for that reason.
3. Options of dynamic modules (`logger.ForRoot`) and `WithShutdownTimeout`
   are fixed before the configuration loads, so a config-driven log level or
   shutdown timeout needs a factory provider or a `config.Load` in main. The
   example uses a `-debug` flag and a constant timeout.
4. Handler names in the startup log and OpenAPI operationIds use the bare type
   name, so `auth.Controller.Login` and `tenants.Controller.Current` would both
   read `Controller.X`; the example names controller types
   `AuthController`, `TenantsController`, `ProjectsController`.
5. CLI `gonest g module` emits `Exports: []gonest.Token{}` (harmless).

## Decisions

- Snippets: `// docs:<name>` ... `// docs:end` regions; `examples/docscheck`
  enforces that every Go block in the guide and README is a verbatim region.
  Regenerate by copying the region (the fill script used is trivial; the test
  names the stale block). Shell output, NestJS TypeScript and generated CLI
  output are `text`/`ts`/`sh` fences and are not checked.
- Error messages and outputs quoted in the guide come from `Example` output
  checks or from the live run, not from memory.
- `examples/saas/internal/...` keeps the example's packages private.
- Middleware runs before guards, so a request with neither token nor tenant
  header gets 400 (tenant) rather than 401; documented in pipeline.md.

## Known gaps

- `examples/saas/cmd/server/main.go` has no test (covered by the live run and
  `TestServeGracefulShutdown`, which uses `Serve` directly).
- Demo users have unsalted SHA-256 password hashes (clearly marked demo only).
- `go install github.com/omyo/gonest/cmd/gonest@latest` in the docs assumes the
  module is published at that path.
